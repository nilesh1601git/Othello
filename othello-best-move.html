How the computer picks a move

The computer lists every legal flip, then keeps the move that looks best after looking ahead. Easy play skips the look-ahead and chooses a legal square at random. Medium and Hard search with alpha-beta, and they score unfinished positions with a fixed table of square values plus mobility.

The short version

  1. Find every empty square where the side to move can bracket at least one enemy disc and flip it.
  2. On Easy, play one of those squares at random and stop.
  3. On Medium and Hard, sort those squares so corners are tried first and squares touching an empty corner are tried last.
  4. Look ahead 1 ply, then 2, and so on, up to the difficulty limit or the time budget. Each finished depth replaces the chosen move. A depth that runs out of time is thrown away.
  5. At every imagined position, Black’s search (when Black is the computer) keeps the larger score, and White’s replies keep the smaller score. The score is a win or loss if the game is already over; otherwise it is the weighted board plus mobility, with disc count added only later in the game.

The logic lives in othello.ai.ComputerPlayer and othello.ai.Difficulty. The desktop window and the web game both call choose.

What each difficulty actually does

Setting How a move is chosen Depth cap Time budget
Easy One uniform random legal move. The search never runs. 1, stored and unused 150 ms, stored and unused
Medium Alpha-beta search, iterative deepening. 4 plies 700 ms
Hard The same search, allowed to go deeper. 7 plies 1.4 s

A ply is one side’s move. Medium can see the computer’s move, the reply, the computer’s next move, and one more reply, when the clock allows the full 4 plies. The default in both the window and the web game is Medium.

What makes a move legal

The board is 8×8. This program labels columns a–h from the left and rows 1–8 from the top, so a1 is the top-left corner. A move is a row and a column. Move.toString prints that label.

Board.legalMoves walks every square from top to bottom, left to right. An empty square is legal when at least one of the eight directions contains one or more enemy discs and then a disc of the player to move. Playing the square places the player’s disc and flips every such line. A square that flips nothing is ignored.

If the side to move has no legal square, and the opponent still has one, that side passes. The search spends one ply on the pass and then lets the opponent play. If neither side has a move, the game is over and the search scores the disc count immediately.

Which move is examined first

Before any score is computed, Medium and Hard sort the legal list with priority. A smaller number is tried sooner. Java’s sort is stable, so squares with the same priority stay in the original top-to-bottom, left-to-right order.

PrioritySquareWhy it is ordered this way
0A corner: a1, h1, a8, h8Corners cannot be flipped later. Trying them first raises the best score quickly, which lets later branches stop early.
1Any other edge squareEdges are safer than the interior once the nearby corner is already taken.
2Every remaining squareOrdinary interior moves.
4A square touching a corner that is still emptyThese are the usual C-squares (straight beside a corner) and X-squares (diagonally beside a corner). They are tried last so a safer move can set a high bar first.

The “touching an empty corner” test runs before the edge test. So b1, next to an empty a1, is priority 4 even though it sits on the edge. After a1 is occupied, b1 is no longer beside an empty corner and falls back to priority 1.

Looking ahead

choose remembers a best move, starting as the first move after the sort. It then calls bestAtDepth for depth 1, then 2, and so on, until maxDepth. When a depth finishes, that move becomes the best and is moved to the front of the list so the next depth tries it first.

The root scores every candidate. It keeps a move only when the new value is strictly greater than the value it already has. The root’s beta bound stays at the top of the integer range, so a root move is never skipped.

Under the root, minimax does the usual alpha-beta cutoff. The computer’s own turns keep the maximum. The opponent’s turns keep the minimum. When beta is less than or equal to alpha, the rest of that node’s moves are skipped, because they cannot change the decision higher up. The search copies the board for every move it tries, so the real game is unchanged.

Depth 1 means: play each of my moves and score the position immediately, with the opponent still to move. Depth 2 also plays the opponent’s best reply, then scores. Each extra depth adds one more ply. A pass consumes a ply as well.

Before every node and every move, the search checks the clock and the cancel flag. If either says stop, it throws SearchExpired. choose catches that and returns the best move from the last depth that finished. A half-finished deeper search does not change the move.

How a position is scored

Every number is from the computer’s own color, called me in the search. A higher number is better for that color.

A finished game

Let the disc difference be my discs minus the opponent’s discs.

I have more discs → 100000 + difference
I have fewer discs → -100000 + difference
Equal discs → 0

The smallest winning score is 100001. The weighted score used during the game stays far below that, so a proven win always beats a merely promising position, and a proven loss always loses to one.

An unfinished position

Three ingredients are added, and the recipe changes with how many empty squares remain.

  • Position. Add the table value of each of my discs. Subtract the table value of each opponent disc.
  • Mobility. My legal-move count minus the opponent’s legal-move count.
  • Disc difference. My discs minus the opponent’s discs. The opening ignores this on purpose: grabbing discs early often hands the opponent the corners.
Empty squaresStageScore
21 or moreOpening, including the start (60 empty)position + 15 × mobility
11 to 20Middleposition + 10 × mobility + 4 × disc difference
10 or fewerEnd25 × disc difference + position ÷ 4 + 4 × mobility

The endgame division is integer division, toward zero, the same as Java’s positional / 4.

The square table

Corners are worth 120. The diagonal neighbor of a corner, the X-square, is worth −40. The edge neighbor, the C-square, is worth −20. Stable edges and the center are mildly positive. Hover a square to read its role.

Corner a1 is worth 120. A disc placed here can never be flipped.

Ties, time, and a cancelled search

The opening

From the standard start, Black’s only legal squares are d3, c4, f5, and e6. They are symmetric. Each has priority 2, and each scores 9 at one ply: position 9, mobility 0, disc difference +3, and the opening formula drops the disc difference. The search keeps the first of them, d3, because a later equal score does not replace the current best. Deeper depths stay tied for the same reason of symmetry, so the tie-break still plays d3.

The clock

The deadline is now + budget in nanoseconds, taken once at the start of choose. Medium has 700 ms and Hard has 1.4 s for the whole deepening loop, shared across every depth. If depth 4 is still running when Medium’s budget ends, the move from depth 3 is what gets played. If even depth 1 is interrupted, the move is the first square after the priority sort, because that is the fallback stored before the loop.

Cancel

The desktop player passes a cancel check into choose, so leaving the position can abandon the search. The web game calls the overload that never cancels. Easy never consults either the clock or the cancel flag.
